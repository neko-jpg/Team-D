## Why

現在のリポジトリには、撮影に不慣れな人が衣類を出品できるまで支援する体験の要件と技術方針はあるが、動作する MVP として実装へ引き渡せる仕様・責務分担・受け入れ条件がない。2日間のハッカソンでは、写真を採点して終わる機能ではなく、AI の案内に従って必要写真を揃え、商品そのものを変えずに出品画像を完成できる中心体験を先に固定する必要がある。

## What Changes

- React + TypeScript + Vite のモバイル Web に、衣類の正面・背面・タグ写真を撮影またはアップロードするステップ型フローを追加する。
- 写真ごとに画像 AI が衣類の有無、撮影種別、品質問題、不足写真、次の行動を限定された構造化結果で返すようにする。
- AI の自由な返答で画面遷移を決めず、アプリ側の状態機械／Reducer が `RETAKE`、`REQUEST_NEXT`、`COMPLETE` の許可された結果だけを処理する。
- 不足写真や撮り直しがある限り、理由と具体的な撮影指示を表示して再撮影できるようにする。
- 元画像を保持したまま、バックエンドで生成した商品マスクを用いて選択背景と合成する編集画面を追加する。
- 編集前後を比較し、ユーザーが背景を採用するか元画像へ戻すかを明示的に承認できるようにする。
- ブラウザへ秘密情報を渡さず、`/api` 経由で画像 AI と背景分離サービスへ接続する開発構成を追加する。Vite のプロキシは開発時の端末テストに限定し、公開範囲と許可オリジンを明示する。
- 採寸、自動撮影、価格推定、着用画像生成、商品自体の生成・改変、ネイティブ Swift／ARKit は MVP の対象外とする。

## Capabilities

### New Capabilities

- `guided-garment-capture`: 撮影ガイド、画像品質・撮影種別の判定、必要写真の進捗、撮り直し／次撮影／完了の伴走フローを扱う。
- `background-preserving-edit`: 現物の商品情報を保持したマスク合成、背景選択、元画像との比較、ユーザー承認を扱う。

### Modified Capabilities

なし。既存の `openspec/specs/` に仕様は存在しないため、今回の MVP 要件を新規 capability として定義する。

## Impact

- 新規フロントエンド: カメラ／ファイル入力、撮影ステップ表示、判定結果表示、進捗管理、背景選択、比較・承認 UI。
- 新規 Node.js API: 画像 AI 呼び出し、構造化判定の検証、rembg／BiRefNet へのマスク生成依頼、エラー・タイムアウト処理。
- 新規依存候補: AI SDK、画像マスクサービス、`react-konva` 等の Canvas 合成、状態管理、テスト用 Vitest／Playwright。
- 開発環境: Vite の `/api` プロキシと HTTPS トンネルによる iPhone Safari／Android Chrome 実機確認。プロキシは本番 API の代替ではないため、環境別 API URL 設定が必要になる。
- データ取扱い: MVP ではアップロード画像を永続保存せず、処理に必要な範囲で一時的に扱う。元画像はクライアントのフロー中に保持し、編集結果はユーザー承認後に出力する。
